# ClipGauge v0.5.16 Quality Benchmark

## Purpose

This benchmark separates candidate recall from final ranking quality.
It measures whether independent, self-contained moments are discovered before
provider scoring chooses finalists.

The benchmark never requires an arbitrary clip count.
A source may legitimately contain one strong moment.

## Legal input boundary

CI uses only deterministic, first-party fixtures.
Owner qualification uses timestamps and labels only.
The repository stores no owner media or transcript.

The owner source is `Wdjh81uH6FU`.
Owner-approved timestamp labels exist for qualification.
Quality tiers remain unassigned.

## Required inputs

- ordered candidate records with `start` and `end`
- ordered recommendation records with `start` and `end`
- owner annotations with `start`, `end`, and relevance
- optional `hook_start` and `payoff_start` points
- source duration in seconds
- requested and actual provider models

Each owner annotation represents one independently valuable story moment.
Several annotations must cover dense sources.

## Metrics

`quality_benchmark.py` computes:

- candidate recall@K
- recommendation precision@K
- nDCG@K
- mean boundary start and end error
- hook coverage
- payoff coverage
- story completeness
- duplicate recommendation rate
- temporal diversity
- false-bait rate

Interval matches use deterministic IoU thresholds.
Boundary matches are one-to-one and reproducible.
False-bait metrics count verified scoring records only.

## Provider comparison

Every run records the requested model and actual model.
Auto-routed OpenRouter runs retain returned model identity.
Runs also record capabilities, schema, rubric, latency, cost, and failures.

Local and cloud runs reuse identical candidate inputs.
They must not rerun upstream ASR or event extraction.
