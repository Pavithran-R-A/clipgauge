# ClipGauge v0.5.16 Quality Benchmark

## Purpose

This benchmark separates candidate recall from final ranking quality.
It measures whether independent, self-contained moments are discovered before
provider scoring chooses finalists.

The benchmark never requires an arbitrary clip count.
A source may legitimately contain one strong moment.

## Required inputs

- ordered candidate records with `start` and `end`
- ordered recommendation records with `start` and `end`
- owner annotations with `start`, `end`, and relevance
- optional `hook_start` and `payoff_start` points
- source duration in seconds
- requested and actual provider models

Each owner annotation represents one independently valuable story moment.
Several annotations must cover dense sources.

## Metric contract

All intervals use half-open time ranges `[start, end)`.
IoU is intersection divided by union.
An interval matches at IoU `>= 0.30`.

Owner-Strong means frozen `relevance == 3`.
Hand modeling is Borderline, with `relevance == 2`.
Strong thresholds use seven owner-Strong labels.
Borderline remains separately reported.

Each metric uses these exact rules:

| Metric | Denominator and matching | Pipeline point |
| --- | --- | --- |
| `candidate_pool_recall` | Unique owner-Strong labels matched by any full-pool candidate, divided by seven. One label counts once. | Before provider scoring |
| `Recall@5` | Unique frozen annotations matched by the first five ranked recommendations, divided by eight annotations. One label counts once. | After provider scoring |
| `NDCG@5` | Each recommendation gains the highest `relevance * IoU` among unmatched annotations at IoU `>= 0.30`; each annotation matches once. DCG uses log base two. IDCG uses the eight frozen relevance values, sorted descending. | After provider scoring |
| Hook coverage | Owner-Strong labels with at least one top-five recommendation containing `hook_start`, divided by seven. | After provider scoring |
| Payoff coverage | Owner-Strong labels with at least one top-five recommendation containing `payoff_start`, divided by seven. | After provider scoring |
| Start boundary error | Matched owner-Strong pairs use maximum-IoU one-to-one matching. Report median absolute start error. Unmatched labels are excluded from this median. | After provider scoring |
| End boundary error | Same one-to-one pairs as start error. Report median absolute end error. Unmatched labels are excluded from this median. | After provider scoring |
| Temporal diversity | Count distinct owner-Strong labels represented in the top five. A recommendation cannot represent two labels. Report count and `count / min(4, eligible Strong labels)`. | After provider scoring |
| False-bait rate | False-positive bait decisions divided by all model-reported bait phrases. A false positive is model-reported bait rejected by verification. Zero reports means zero rate, with zero false positives. | After scoring verification |

The acceptance report also preserves mean boundary errors.
Threshold decisions use the specified medians.
Matching is deterministic and one-to-one.
Multiple predictions cannot match one label.
Duplicate predictions cannot inflate recall.
The Borderline label never satisfies Strong thresholds.

Candidate-pool metrics use the generated candidate order only for K.
Full-pool recall ignores order.
Recommendation metrics use final ranked order.
The benchmark does not require a fixed clip count.
