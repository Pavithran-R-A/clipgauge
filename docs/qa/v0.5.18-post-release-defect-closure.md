## Findings

### R01 — Local provider routing

- Original symptom: Private Ollama or LM Studio runs could silently become ClipGauge Local; cloud modes were not aligned with provider identity.
- Root cause: Provider locality and quality-mode mapping were duplicated across Creator and preflight.
- Affected files: `app/src/providerContract.ts`, `app/src/components/Studio.tsx`, `app/src/App.tsx`, `pipeline/clipgauge_pipeline/config.py`, `pipeline/clipgauge_pipeline/preflight.py`, provider tests.
- Fix: Added one typed execution resolver. Local private runs preserve the selected local provider. Balanced and Best require a configured cloud provider. Backend and frontend enforce the same contract.
- Regression: `providerContract.test.ts`, `Studio.test.tsx`, configuration and preflight tests cover ClipGauge Local, Ollama, LM Studio, Groq, OpenRouter, Custom, and cloud/private blocking.
- Qualification: Studio actual run arguments passed for all required provider/model combinations. Ollama and LM Studio services were unavailable on this host, so live service scoring was not claimed.
- Disposition: Closed by contract and regression coverage.

### R02 — Provider Center inspect versus select

- Original symptom: Clicking a provider card could change Creator before “Use for next clip”.
- Root cause: Inspection state called the parent selection callback.
- Affected files: `app/src/components/ProviderCenter.tsx`, `app/src/v050InformationArchitecture.test.tsx`.
- Fix: Card clicks now change only `activeId`. Credentials, model refresh, endpoint edits, and connection tests do not commit selection. Only “Use for next clip” commits the inspected provider.
- Regression: Browse/back, test/back, save/back, commit, multi-card commit, prop-update, and model-persistence tests pass.
- Qualification: Provider Center suite passed with 87 tests in the focused provider/information-architecture run.
- Disposition: Closed.

### R03 — Shared provider readiness

- Original symptom: Credential presence could enable a mode before endpoint, model, capability, or service readiness existed.
- Root cause: Creator used a credential shortcut while Provider Center and preflight had richer facts.
- Affected files: `app/src/providerContract.ts`, `pipeline/clipgauge_pipeline/readiness.py`, `pipeline/clipgauge_pipeline/preflight.py`, `app/src/App.tsx`, `app/src/components/ProviderCenter.tsx`.
- Fix: Added typed readiness fields for credentials, endpoints, models, compatibility, runtime, service, blocking reasons, and mode capabilities. Cloud qualification requires a recent successful provider qualification record.
- Regression: TypeScript provider-contract tests and Python preflight/config tests cover Cloudflare endpoints, Custom endpoints/models, local service absence, model availability, and cloud mode protection.
- Qualification: Creator now shows the exact missing action instead of treating an API key as sufficient.
- Disposition: Closed.

### R04 — Truthful YouTube status timestamps

- Original symptom: Readiness refresh could display a timestamp as a public compatibility test without a public transfer.
- Root cause: Dependency inspection, provider self-test, and public transfer shared one semantic timestamp.
- Affected files: `pipeline/clipgauge_pipeline/ingest/youtube_compat.py`, `pipeline/clipgauge_pipeline/ingest/ytdlp.py`, `app/src/components/SetupCenter.tsx`, `app/src/types.ts`.
- Fix: Separate `dependency_checked_at`, `provider_self_tested_at`, and `public_transfer_verified_at`. Only a successful real public transfer writes public verification. Provider-version mismatches invalidate old public claims.
- Regression: YouTube lifecycle/readiness tests cover refresh, self-test, stale verification, and provider-version mismatch. Setup tests cover separate display labels.
- Qualification: A real transfer on 2026-09-14 updated the truthful record with bgutil `2.0.0`, yt-dlp `2026.08.19`, method `bgutil-http`.
- Disposition: Closed.

### R05 — Partial YouTube provider repair

- Original symptom: A partially extracted source tree could pass readiness while later builds failed repeatedly.
- Root cause: Source readiness checked too few archive inputs and repair was not complete for all managed partial states.
- Affected files: `pipeline/clipgauge_pipeline/ingest/youtube_compat.py`, `pipeline/tests/test_v053_setup_readiness.py`.
- Fix: Validate the complete pinned server/plugin input set, repair missing dependencies, rebuild into staging, validate outputs, and atomically replace managed trees. Interrupted staging and backup paths are cleaned only within ClipGauge-owned trees.
- Regression: Tests cover missing tsconfig/source files, malformed manifests, partial and zero-byte plugins, missing Node/npm/build/modules, stale adjacent trees, interrupted staging, archive integrity, listener conflicts, command failures, and repair twice.
- Qualification: Managed bgutil source, build, plugin, Node, npm, and dependencies passed the post-repair readiness contract.
- Disposition: Closed.

### R06 — bgutil loopback qualification

- Original symptom: Dual-stack launch syntax had only command-string coverage.
- Root cause: Actual bgutil CLI behavior had not been proven by a real process.
- Affected files: `pipeline/clipgauge_pipeline/ingest/youtube_compat.py`, `pipeline/tests/test_v053_provider_lifecycle.py`.
- Fix: Retained bgutil `2.0.0`, used its comma-separated host list, and kept process ownership and clean shutdown explicit.
- Regression: Lifecycle tests cover startup, health, version mismatch, occupied ports, IPv4/IPv6, and repeated start/stop.
- Qualification: Real Windows process returned version `2.0.0` on both `127.0.0.1:4416` and `[::1]:4416`. Windows listeners were exactly `127.0.0.1` and `::1`; no `0.0.0.0` or LAN bind appeared. Stop and restart both passed. The upstream CLI source is the pinned [bgutil 2.0.0 release](https://github.com/Brainicism/bgutil-ytdlp-pot-provider).
- Disposition: Closed.

### R07 — Long-form low-memory ASR

- Original symptom: Owned WAV loading duplicated the complete PCM byte buffer and float array, creating avoidable memory spikes.
- Root cause: Whole-file `read` plus `frombuffer(...).astype(float32)` was used before transcription.
- Affected files: `pipeline/clipgauge_pipeline/asr/audio.py`, `pipeline/clipgauge_pipeline/asr/stage.py`, `app/src/App.tsx`.
- Fix: Validate RIFF structure and PCM constraints, cap analysis audio at 256 MiB, memory-map the PCM payload, and retain only the transcription-compatible float32 view. Typed resource failures map to `ASR_RESOURCE_LIMIT`.
- Regression: Audio tests cover tiny, normal, malformed, truncated, wrong-format, zero-frame, oversized-declaration, allocation-path, and typed fallback cases. Production code contains no `whisperx.load_audio()` path.
- Qualification: Genuine CPU ASR passed with CPU, int8, batch 1, low-memory policy, CTranslate2 `4.8.1`, one usable segment, and 11 seconds of normalized audio. Physical i5-8265U / 8 GB retest remains deferred.
- Disposition: Closed for the supported bounded path; physical-device validation deferred.

### R08 — Result-schema compatibility

- Original symptom: Historical score shapes could fail Review despite valid rendered outputs.
- Root cause: Normalization handled isolated historical forms and could mutate or discard safe metadata.
- Affected files: `app/src/jobResultsValidation.ts`, `app/src/types.ts`.
- Fix: Added immutable generic normalization for factor and additive bonus forms, numeric/string story values, missing historical bait reasons, successful no-recommendation results, and safe diagnostic metadata. Malformed score shapes are rejected.
- Regression: Fixture matrix covers v0.5.16, v0.5.17, current results, factor/bonus adjustments, no recommendations, unknown metadata, no mutation, and malformed scores.
- Qualification: Matrix passed 10 tests. Historical results open through normalization without rerunning the pipeline.
- Disposition: Closed.

### R09 — Review-load concurrency and retry

- Original symptom: Late result responses could overwrite a newer session or retry state.
- Root cause: Result loading lacked complete request, active-job, and mounted-component identity checks.
- Affected files: `app/src/App.tsx`, `app/src/App.test.tsx`.
- Fix: Gate result application by request ID, active job ID, and mounted state. Review retry only calls `jobResults`; it does not rerun ingest, ASR, scoring, or rendering.
- Regression: Tests cover job A versus job B, Sessions switching, multiple retries, unmounted completion, preserved active and diagnostic IDs, successful retry, and no `runJob`/`resumeJob` calls.
- Qualification: App suite passed 37 tests before the final focused additions; full frontend suite now passes 283 tests.
- Disposition: Closed.

### R10 — Elapsed-time lifecycle

- Original symptom: Preflight-blocked attempts could show zero elapsed time, and a second timer reset could occur before execution.
- Root cause: Attempt start, terminal freeze, preflight failure, cancellation, and Review loading were not consistently separated.
- Affected files: `app/src/App.tsx`, `app/src/components/Studio.tsx`, `app/src/App.test.tsx`.
- Fix: Start once per attempt, count meaningful preflight time, freeze terminal elapsed values, clear elapsed on new attempts and session switches, and keep Review retry timer-free.
- Regression: Tests cover success, failure, cancel, preflight block, resume, new job, job switch, and Review retry.
- Qualification: Full frontend suite passes with frozen terminal elapsed behavior.
- Disposition: Closed.

### R11 — Stale setup and runtime notices

- Original symptom: Old repair or provider warnings could remain visible during unrelated work.
- Root cause: Notice cleanup was not consistently tied to job and provider boundaries.
- Affected files: `app/src/App.tsx`, `app/src/components/Studio.tsx`.
- Fix: Clear notices on new attempts and provider switches, invalidate stale result requests during navigation, and route Setup local selection through the same provider-switch hygiene.
- Regression: App tests cover stale notice clearing, preflight timing, and result-load races.
- Qualification: No stale notice regression appears in the full frontend suite.
- Disposition: Closed.

### R12 — Provider, model, and privacy UI truth

- Original symptom: UI copy could imply ClipGauge Local even when another local provider was selected; model and locality summaries could diverge from execution.
- Root cause: Static mode copy and selected-card state were separate from actual execution values.
- Affected files: `app/src/components/Studio.tsx`, `app/src/components/Studio.test.tsx`, `app/src/components/ProviderCenter.tsx`, `app/src/App.tsx`.
- Fix: Display actual provider, exact model, mode, and locality. Private copy now refers to the selected local provider. Cloud data-boundary copy appears only for cloud modes. Provider cards expose `aria-pressed`, committed selection, and visible disabled reasons.
- Regression: Studio actual-argument tests and Provider Center information-architecture/accessibility tests pass.
- Qualification: Fresh packaged Setup UI captured at 1366x768 with per-monitor DPI evidence. Full frontend suite passes 283 tests.
- Disposition: Closed.

### R13 — Setup cache efficiency

- Original symptom: Opening Setup could repeat expensive inventory, GPU, or YouTube checks despite recent valid results.
- Root cause: Cache identity, TTL, and public-transfer status were coupled or incomplete.
- Affected files: `app/src/setupInventoryCache.ts`, `app/src/components/SetupCenter.tsx`, related tests.
- Fix: Recent validated inventory skips redundant native inventory checks. Version and manifest identity remain part of cache validity. GPU, YouTube dependencies, self-test, and public transfer keep separate statuses. Explicit Refresh and repair still force affected checks.
- Regression: Invocation-count and cache tests cover fresh, expired, future-dated, missing-identity, version-mismatch, and forced-refresh behavior.
- Qualification: Fresh packaged Setup launch passed without claiming public YouTube verification from local cache inspection.
- Disposition: Closed.

### R14 — Current documentation and version surfaces

- Original symptom: Active README fallback wording referenced an obsolete release, and current version surfaces needed stabilization alignment.
- Root cause: Current documentation was not updated with the post-release closure version.
- Affected files: `README.md`, `INSTALL.md`, `TROUBLESHOOTING.md`, `CHANGELOG.md`, package/Cargo/Python/About version surfaces.
- Fix: Updated active surfaces to `0.5.18`, added a stabilization defect-closure changelog entry, and changed fallback wording to “Fallback if the current release has issues” while retaining the v0.5.3 local-media warning. Historical v0.4 and v0.5.17 records remain historical.
- Regression: `scripts/check-version-consistency.py` passes. Bounded documentation scan finds no stale v0.5.12 fallback wording in active docs.
- Qualification: Historical bgutil `1.3.2` references remain only in historical documents; current provider documentation states `2.0.0`.
- Disposition: Closed.

### R15 — Bounded adjacent-subsystem sweep

- Original symptom: The touched boundaries risked duplicated state, stale promises, hidden substitutions, incomplete managed-tree checks, and retry recomputation.
- Root cause: The review identified the concrete defects recorded in R01–R14.
- Affected files: Provider selection, readiness, preflight, Setup caching, YouTube lifecycle, ASR loading, result loading, timing, and notices.
- Fix: Reviewed the immediate boundaries with targeted searches and regression tests. No additional reproducible project-owned defect was found beyond R01–R14.
- Regression: Full frontend, Python, Rust, accessibility-contract, and security gates listed below pass.
- Qualification: Generated runtime, model, and media artifacts remain outside staged source changes.
- Disposition: Closed; zero known reproducible project-owned defects remain in this acceptance matrix.
