## Concrete workflow comparison

| Workflow | AutoClip reference behavior | ClipGauge v0.6.2 direction |
| --- | --- | --- |
| First import | Local video, YouTube, Bilibili, and optional SRT | Local or URL import, with subtitle support |
| URL failure | Troubleshooting and upload fallback guidance | Stable error copy, bounded fallback, local fallback |
| Local import | Desktop and web import paths | Native session identity and terminal state |
| Session history | Projects, collections, and CLI-oriented workflows | Source labels, resumable state, failed-session cleanup |
| Progress | Detailed analysis and generation stages | Three user phases over internal checkpoints |
| Model setup | Provider and model configuration | Setup tabs with quick and advanced controls |
| Subtitle handling | Optional SRT input | Existing SRT, VTT, and platform-caption paths |
| Collections | Clip organization and collection workflows | Existing review and collection workflows |
| Troubleshooting | README troubleshooting and provider guidance | Setup diagnostics and technical-details disclosure |

## Product-quality deltas

The repair pass addresses these ClipGauge gaps:

1. Failed sessions now identify their source.
2. Terminal state survives application refresh.
3. YouTube failures expose actionable primary copy.
4. Diagnostic identifiers move behind technical details.
5. Progress shows three meaningful phases.
6. Creation intent stays visible.
7. Advanced controls stay available, but collapsed.
8. Setup navigation reduces first-run density.

## Deliberate differences

AutoClip documents web, Docker, CLI, MCP, collections, and current publishing workflows. Those are not being copied into this patch. ClipGauge remains a local-first desktop product. This comparison targets import, failure recovery, sessions, progress, setup, and creation clarity.

The AutoClip README also describes a web interface. The rendered source did not expose a directly inspectable screenshot URL during this audit. Therefore, no screenshot-based visual claim is made here.

## Evidence boundary

This comparison uses public README behavior only. It does not claim parity. Windows screenshots and real YouTube qualification require separate fresh evidence.
